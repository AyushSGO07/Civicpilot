# Plan 03-03: Gemini Multimodal OCR Extraction & Interactive Verification Modal

<objective>
Integrate the official Google GenAI SDK (`google-genai`) to parse uploaded documents into structured citizen profile fields (D-04: Gemini Multimodal OCR Extraction, DOC-03), and build an interactive verification modal allowing citizens to inspect, select, and merge extracted data directly into their profile (D-06: Integrity & Human Verification, DOC-04).
</objective>

<execution_context>
- specs.md §3.4 (Document Vault OCR) & §7 (AI Layer)

- .planning/phases/03-secure-document-vault-multimodal-ocr-extraction/03-RESEARCH.md (Google GenAI SDK Integration)
- .planning/phases/03-secure-document-vault-multimodal-ocr-extraction/03-UI-SPEC.md (§3.2 OCR Modal)
</execution_context>

<threat_model>
ASVS Level 1:
- Mask national identity numbers (e.g., Aadhaar `XXXX-XXXX-1234`, PAN `XXXXX1234X`) in extracted OCR outputs.
- Never commit extracted fields to citizen profile without explicit user review and confirmation.
- Handle malformed or unreadable documents gracefully with clear error feedback.
</threat_model>

Implement `backend/app/services/ocr.py` using `google-genai`:
1. Define Pydantic schema `ExtractedDocumentData`:
   - `document_type`: str
   - `full_name`: Optional[str]
   - `date_of_birth`: Optional[str]
   - `gender`: Optional[str]
   - `id_number_masked`: Optional[str]
   - `state`: Optional[str]
   - `district`: Optional[str]
   - `pincode`: Optional[str]
   - `annual_income`: Optional[float]
   - `social_category`: Optional[str]
   - `institution_name`: Optional[str]
   - `course`: Optional[str]
   - `academic_score`: Optional[str]
   - `confidence_score`: float
2. Function `extract_document_fields(file_bytes: bytes, mime_type: str, document_type: str) -> ExtractedDocumentData`:
   - Calls `genai.Client().models.generate_content(model="gemini-2.5-flash", ...)` with JSON schema.
   - Provides deterministic parsing fallback if `GEMINI_API_KEY` is not configured or in offline test environment.
</action>

</read_first>
<action>
Implement OCR endpoints in `backend/app/routers/documents.py`:
1. `POST /api/documents/{doc_id}/ocr`:
   - Fetches document by ID.
   - Invokes `extract_document_fields`.
   - Saves extracted data into document `extracted_information` and updates `verification_status` to `'Extracted'`.
   - Returns extracted structured fields to client.
2. `POST /api/documents/{doc_id}/confirm`:
   - Accepts citizen-confirmed fields payload.
   - Updates citizen profile in `public.citizen_profiles` (`_PROFILES_STORE`).
   - Updates document `verification_status` to `'Verified'`.
   - Returns updated citizen profile and document status.
</action>
<acceptance_criteria>
- `POST /api/documents/{id}/ocr` returns extracted JSON.
- `POST /api/documents/{id}/confirm` updates citizen profile and sets status to 'Verified'.
</acceptance_criteria>
<verify>
Run `pytest backend/tests/test_documents.py -v`.
</verify>
</task>

Build interactive OCR Verification & Profile Merge Modal in `frontend/app/documents/page.tsx`:
1. "Run AI OCR" button on each document card triggers `POST /api/documents/{id}/ocr` with loading spinner.
2. Opens OCR Verification Modal displaying:
   - Header with document type, filename, and AI confidence score pill.
   - Structured comparison table: Field Name, Extracted Value, Current Profile Value, and inclusion checkbox.
   - Editable inputs so the citizen can correct any misread character before confirmation.
3. Primary CTA: "Sync Selected Fields to Citizen Profile" calling `POST /api/documents/{id}/confirm`.
4. Visual confirmation toast and badge update to "Verified".
</action>
