# Plan 02-01: Database Schema, Backend Profile Models & FastAPI Endpoints

<objective>
Define the PostgreSQL schema for citizen profiles with Row Level Security (D-04: Citizen Profile PostgreSQL Schema & RLS) and implement the modular FastAPI profile router with strict Pydantic models and automated tests (D-06: FastAPI Profile Endpoints).
</objective>

<execution_context>
- specs.md §3.3 (Citizen Profile) & §12 (API Structure)
- .planning/phases/02-authentication-citizen-profile-management/02-CONTEXT.md (D-04, D-06)
- .planning/phases/02-authentication-citizen-profile-management/02-RESEARCH.md (Database Schema & Pydantic models)
- .planning/phases/02-authentication-citizen-profile-management/02-VALIDATION.md (Pytest configuration)
</execution_context>

<threat_model>
ASVS Level 1:
- Ensure Row Level Security (RLS) is explicitly enabled on `citizen_profiles` so users cannot read or mutate other citizens' profiles.
- Verify user authorization token on all mutating profile endpoints (`PUT /api/profile`).
- Prevent SQL injection by using parameterized ORM / query builder patterns.
</threat_model>

<action>
Create `database/schema.sql` containing the DDL for `public.citizen_profiles` table linked via foreign key to `auth.users(id)`:
- Personal fields: `full_name`, `date_of_birth`, `gender`, `contact_number`
- Address fields: `state`, `district`, `pincode`
- Educational fields: `education_level`, `institution_name`, `course`, `academic_year`
- Voluntary eligibility fields: `occupation`, `annual_income`, `social_category`, `disability_status`, `minority_status`
- Timestamps: `created_at`, `updated_at`
- Row Level Security (RLS) policies allowing users to SELECT, INSERT, and UPDATE only their own profile (`auth.uid() = id`).
</action>
<acceptance_criteria>
- `database/schema.sql` defines `CREATE TABLE IF NOT EXISTS public.citizen_profiles`.
- RLS enabled with `ALTER TABLE public.citizen_profiles ENABLE ROW LEVEL SECURITY;`.
- RLS policies define access restricted to `auth.uid() = id`.
</acceptance_criteria>
<verify>
Inspect `database/schema.sql` to confirm all fields and RLS policies are present.
</verify>
</task>

<action>
Implement backend profile models and API router:
1. Create `backend/app/models/profile.py` with Pydantic schemas:
   - `CitizenProfileBase`: Personal, address, educational, and voluntary eligibility fields with validation.
   - `CitizenProfileUpdate`: Optional fields for partial updates.
   - `CitizenProfileResponse`: Full schema including `id`, `created_at`, `updated_at`.
2. Create `backend/app/routers/profile.py` mounted at `/profile`:
   - `GET /profile`: Returns authenticated user's citizen profile.
   - `PUT /profile`: Updates or creates user profile with validated input.
   - Dependency for auth verification with mock fallback for local tests.
3. Update `backend/app/main.py` to include `profile.router` under `settings.API_PREFIX`.
</action>

</acceptance_criteria>
