# Plan 04-01: Government Scheme Database Schema, Official Seed Dataset & Search Endpoints

<objective>
Define the PostgreSQL schema for government services (D-02: Database Schema & Caching), build the verified official Indian government scheme dataset and search engine (D-01: Official Data & Zero Dummy Data, D-04: Natural Language Search & Filtering), and implement FastAPI `/api/services` endpoints with automated pytest coverage (D-03: FastAPI Service Discovery Endpoints).
</objective>

<execution_context>
- specs.md §3.5 (Explore Government Services), §8 (Live Data & No-Dummy-Data Compliance), §9 (Database Design)
- .planning/phases/04-live-government-scheme-discovery-search/04-CONTEXT.md (D-01, D-02, D-03, D-04)
- .planning/phases/04-live-government-scheme-discovery-search/04-RESEARCH.md (Official Schemas Dataset & Search Engine)
- .planning/phases/04-live-government-scheme-discovery-search/04-VALIDATION.md (Pytest configuration)
</execution_context>

<threat_model>
ASVS Level 1:
- Zero fabricated schemes: All services must originate from official government endpoints.
- Sanitize and escape search query parameters to prevent injection attacks.
- Public read access for active schemes; prevent unauthorized scheme modification.
</threat_model>

<task>
<id>04-01-02</id>
<read_first>
- backend/app/main.py
- .planning/phases/04-live-government-scheme-discovery-search/04-RESEARCH.md
</read_first>
<action>
1. Create `backend/app/models/service.py` with Pydantic schemas:
   - `GovernmentServiceBase`: Core scheme fields.
   - `GovernmentServiceResponse`: Complete schema with `id`, timestamps, and URLs.
   - `ServiceSearchQuery`: Query model supporting `q`, `category`, `state`.
2. Create `backend/app/services/scheme_search.py`:
   - Curate 8 authentic official government schemes (PM-USP Scholarship, PM-KISAN, PM-JAY, Post Matric SC, PMEGP MSME, Sarathi Parivahan, NAPS, PMAY-U) with exact official URLs.
   - Implement `search_services(query: Optional[str], category: Optional[str], state: Optional[str]) -> List[GovernmentServiceResponse]` with tokenized keyword matching and relevance scoring.
3. Create `backend/app/routers/services.py`:
   - `GET /api/services`: List/search services with query params `q`, `category`, `state`.
   - `GET /api/services/{service_id}`: Retrieve single service details.
4. Mount `services.router` in `backend/app/main.py` under `settings.API_PREFIX`.
</action>
<acceptance_criteria>

- `backend/app/services/scheme_search.py` contains 8 verified official schemes with official URLs.
- `backend/app/routers/services.py` implements search and detail endpoints.
- `backend/app/main.py` mounts the services router.
</acceptance_criteria>
