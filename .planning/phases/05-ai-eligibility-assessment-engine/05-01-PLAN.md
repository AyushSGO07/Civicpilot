# Plan 05-01: Implement Backend AI Eligibility Reasoning Service and Evaluation API

## Objective
Create the backend evaluation engine using Gemini 2.5 Flash (`google-genai` SDK) with deterministic offline fallback, structured Pydantic schemas, official citations, missing field detection, and the evaluation endpoint `POST /api/services/{id}/evaluate`.

## Step-by-Step Implementation

### Step 1: Create Pydantic Models for Eligibility Assessment
File: `backend/app/models/eligibility.py`
- Define:
  - `EligibilityStatus = Literal["Likely Eligible", "Likely Ineligible", "More Information Required"]`
  - `CriterionStatus = Literal["Satisfied", "Not Satisfied", "Missing Info"]`
  - `CriterionEvaluation`: `criterion_name`, `condition`, `citizen_value`, `status`, `reasoning`, `official_citation`
  - `EligibilityEvaluationRequest`: Optional citizen profile data override, or empty to read user profile from database/token.
  - `EligibilityEvaluationResponse`: `service_id`, `service_name`, `status`, `summary`, `confidence_score`, `criteria`, `missing_fields`, `next_steps`, `disclaimer`

### Step 2: Implement Eligibility Reasoning Service
File: `backend/app/services/eligibility.py`
- Implement `evaluate_scheme_eligibility(scheme: GovernmentServiceResponse, profile: CitizenProfileResponse) -> EligibilityEvaluationResponse`:
  - When `GEMINI_API_KEY` is available:
    - Use `google-genai` client with `gemini-2.5-flash`.
    - Provide structured system prompt explaining government scheme criteria analysis and citation requirements.
    - Set `config=types.GenerateContentConfig(response_mime_type="application/json", response_schema=EligibilityEvaluationResponse)`.
  - When `GEMINI_API_KEY` is not available or upon failure:
    - Execute deterministic rule-based evaluation:
      - Compare `profile.annual_income` vs `scheme.eligibility_criteria.get("max_annual_income")`
      - Compare `profile.education_level` vs `scheme.eligibility_criteria.get("education_level")`
      - Compare `profile.occupation` vs `scheme.eligibility_criteria.get("occupation")`
      - Compare `profile.social_category` vs `scheme.eligibility_criteria.get("social_category")`
      - Compare `profile.state` vs `scheme.state` (if state != "Central")
      - Detect missing fields needed by criteria and flag `More Information Required` + `missing_fields`.
      - Attach verified citations (e.g. "Section 3.2 of PM-USP Scholarship Guidelines", "Clause 4(a) of PM-KISAN Operational Guidelines").

### Step 3: Implement Endpoint in Services Router
File: `backend/app/routers/services.py`
- Add route `POST /api/services/{service_id}/evaluate`:
  - Fetch scheme from service catalog / database. If missing, raise 404.
  - Extract citizen profile:
    - If request body supplies profile overrides, use them.
    - Else if Bearer token is provided, fetch profile from Supabase/database or return demo profile.
    - Else use default citizen profile for preview evaluation.
  - Call `evaluate_scheme_eligibility(scheme, profile)` and return `EligibilityEvaluationResponse`.

### Step 4: Write Automated Pytest Suite
File: `backend/tests/test_eligibility.py`
- Test cases:
  1. `test_evaluate_eligible_citizen`: PM-USP with qualifying student profile returns `Likely Eligible`.
  2. `test_evaluate_ineligible_citizen`: PM-USP with high annual income returns `Likely Ineligible`.
  3. `test_evaluate_missing_info`: Incomplete profile returns `More Information Required` with non-empty `missing_fields`.
  4. `test_evaluate_citations`: Every criterion evaluation has valid `official_citation`.
  5. `test_evaluate_disclaimer`: Response includes statutory advisory disclaimer.
  6. `test_evaluate_service_not_found`: Non-existent service ID returns 404.
